### 1.2 风险概要

**段落结构（固定2部分，顺序不可调）**：

**第一部分：评分与趋势**——固定2行，按顺序输出：

1. 当前评分与风险等级：`**当前评分：X分，风险等级：取值asset_info中的RISK_LEVEL，需检查是否取值正确**`

   **取数路径**：X = scoreHistory 最后一条的 `score`，风险等级 = 最后一条的 `riskLevel` 字段值（直接取，禁止自行按分数推算等级）。

2. 30天评分走势：根据 scoreHistory 的起点、终点数据及各自 `riskLevel`，按下表场景输出（scoreHistory 为空时输出"历史数据暂无评分"）：

   **判定步骤**：
   - X = scoreHistory 最早一条的 `score`，起点等级 = 最早一条的 `riskLevel`
   - Y = scoreHistory 最近一条的 `score`，终点等级 = 最近一条的 `riskLevel`
   - 计算 |Y-X| 分差

   **输出规则**（按命中场景输出，句式不可调整）：

   | 场景 | 句式 |
   |------|------|
   | 起点等级 ≠ 终点等级 且 Y<X | `30天评分走势：从X分（[起点等级]）下滑至Y分（[终点等级]），资产健康度显著恶化。` |
   | 起点等级 ≠ 终点等级 且 Y>X | `30天评分走势：从X分（[起点等级]）回升至Y分（[终点等级]），资产健康度有所改善。` |
   | 起点等级 = 终点等级 = 健康 且 分差<5 | `30天评分走势：评分基本稳定，资产持续保持健康状态。` |
   | 起点等级 = 终点等级 = 低危 且 分差<5 | `30天评分走势：评分小幅波动，整体处于低风险状态。` |
   | 起点等级 = 终点等级 = 中危 且 分差<5 | `30天评分走势：评分在中危区间徘徊，存在需治理的风险。` |
   | 起点等级 = 终点等级 = 高危 且 分差<5 | `30天评分走势：评分持续停留在高危区间，资产长期处于不健康状态。` |
   | 起点等级 = 终点等级 = 严重 且 分差<5 | `30天评分走势：评分长期处于严重区间，资产极度不健康。` |
   | 起点等级 = 终点等级（低危及以下） 且 分差≥5 | `30天评分走势：从X分[升/降]至Y分，维持在[等级]区间，资产长期不健康。` |
   | 起点等级 = 终点等级（中危及以上） 且 分差≥5 | `30天评分走势：从X分[升/降]至Y分，维持在[等级]区间。` |

   **关键约束（不可违反）**：
   - 等级一律取 scoreHistory 中的 `riskLevel` 字段值，**禁止**自行按分数区间判定等级
   - 同等级稳定场景（分差<5）：**不输出具体分数**，按终点等级给出健康度定性即可
   - 跨等级或同等级分差≥5的变化场景：必须给出 X、Y 的具体数值与各自等级
   - 高危及严重等级稳定场景：**禁止**使用"稳定/平稳/良好"等中性偏褒义词，必须明确点出"资产长期不健康/极度不健康"等真实状态

>
> **当前评分：50分，风险等级：严重。**

**第二部分：高危攻击路径**——最多3条，每条一段话，固定结构。

### 2.1 关键转折点

**段落结构（固定）**：对每个评分下降节点，单独一段话展开。

**每段固定结构**（按顺序拼接）：

`**[X月X日]**：评分从[X]分（[起点等级]）降至[Y]分（[终点等级]）[，跨越风险等级：由[起点等级]滑落至[终点等级]]。当日[具体事件清单——告警列出名称/风险等级/攻击者IP/攻击结果，漏洞列出CVE编号/风险等级/是否远程利用]。[一句话归因——明确是告警驱动/漏洞驱动/情报驱动/历史数据失效，标注推测的须注明"推测"]。`

**风险等级标注规则**（按1.2节等级表）：
- 起点分、终点分必须分别标注所属等级
- 若起点终点跨等级（如75分降至67分，由中危跌入高危），必须显式输出"跨越风险等级：由[起点等级]滑落至[终点等级]"子句
- 若起点终点同等级（如72分降至71分，均为中危），不输出"跨越风险等级"子句，但仍需在分值后标注等级

**归因细化要求**（每段必须明确命中以下一种，禁止笼统说"推动评分下降"）：
- **告警驱动**：列出告警类别（漏洞利用/侦察投递/命令控制/网页篡改等）+ 条数 + 是否有攻击成功
- **漏洞驱动**：列出CVE + 风险等级 + 是否远程利用 + 是否在野利用
- **情报驱动**：说明情报来源（恶意IP/恶意域名/恶意样本）+ 命中次数
- **历史数据失效**：明确失效类型（10天告警窗口/30天漏洞窗口等）+ 失效后剩余计数
- **数据不充分**：须注明"（推测）"并说明推测依据，禁止编造未提供的归因

**其他具体要求**：
- 告警事件驱动的下降：列出具体告警名称、风险等级、攻击者IP、攻击结果（成功/失败），从 `keyChanges` 获取
- 漏洞驱动的下降：列出具体CVE编号、风险等级、是否远程利用
- 情报驱动的下降：说明情报命中率变化
- 数据不充分时：说明推测原因（"推测为历史告警超出10天窗口期失效"），但要标注是推测
- 纯解释性，不提修复建议（修复建议由1.3输出）
- 评分上升节点不调查，合并一句话带过（"X月X日评分回升至Y分（[终点等级]），推测为部分历史告警超出10天计算窗口失效"）
- 评分无变化时整个 2.1 按终点等级（scoreHistory 最后一条的 `riskLevel`）差异化输出单行（不再展开转折点）：

  | 终点等级 | 输出句式 |
  |---------|---------|
  | 健康 | `评分基本稳定，资产持续保持健康状态。` |
  | 低危 | `评分小幅波动，整体处于低风险状态。` |
  | 中危 | `评分在中危区间徘徊，存在需治理的风险。` |
  | 高危 | `评分持续停留在高危区间，资产长期处于不健康状态。` |
  | 严重 | `评分长期处于严重区间，资产极度不健康。` |

> 示例：
> **5月20日**：评分从75分（中危）降至67分（高危），跨越风险等级：由中危滑落至高危。当日新增3条高危告警——来自IP 1.2.3.4的SQL注入攻击（高危，成功）、来自IP 5.6.7.8的漏洞扫描探测（中危，失败）、以及1条Webshell上传尝试（高危，失败）。告警事件风险分显著上升，告警驱动下降。
>
> **5月25日**：评分从67分（高危）降至64分（高危）。当日无新增告警，但扫描引擎新发现2个高危漏洞（CVE-2024-21733、CVE-2024-XXXX），其中CVE-2024-21733支持远程利用。漏洞弱密码风险分上升，漏洞驱动下降。
>
> **5月28日**：评分回升至72分（中危），推测为部分历史告警超出10天计算窗口失效。

## 通用规则

- 折叠格式：第2-3章用 `<details><summary>` 包裹，默认折叠
- 证据链接格式：`> **查看[章节名]**：[章节名](#锚点)`，只链接有数据的章节
- 可用链接锚点（只组合有数据的，用 `|` 分隔）：

| 有这类数据 | 链接到 |
|-----------|-------|
| 评分下降转折点 | `[关键转折点](#关键转折点)` |
| 漏洞(超危/高危) | `[紧急漏洞](#紧急漏洞)` |
| 未处置告警/事件 | `[活跃攻击](#活跃攻击)` |
| 暴露/风险端口 | `[基础防线与暴露面](#基础防线与暴露面)` |
| 当前威胁总览 | `[当前威胁](#第3章)` |

- 无数据处理：委婉告知"暂未查询到相关数据"，整节只输出一行
- 字段名转换：ASSET_LEVEL$NAME → "资产等级"，IS_EXPOSURE → "暴露面"，HANDLE_STATUS → "处置状态" 等
- CVSS解析：解析CVSS向量，用通俗语言说明利用难度（"攻击者可通过互联网，无需账号密码即可远程利用"）
- 数字格式：评分、CVSS、数量统一用阿拉伯数字，不写"两/三个"等汉字数词
- 时间格式：统一"YYYY-MM-DD HH:mm"，不写"昨天/上周"
- **报告结束标记（硬性约束）**：报告以第3章末尾的 `</details>` 标签作为**唯一结束符**。该标签的 `>` 字符之后**不得输出任何内容**——包括但不限于：总结段、归纳段、"以上就是..."、总体评价、再次列出的风险清单、补充建议、署名、感谢语、分隔线、空行后追加的文字。如果你想加一句收尾话，**忍住，一个字都不要写**。
