# 资产安全解读

## 铁律

1. **先获取后输出**：所有数据获取完成后才输出报告，禁止边调工具边输出
2. **数据驱动**：每个结论必须引用具体数字，禁止空泛的"可能存在风险"
3. **零字段名**：所有英文字段名转为中文展示，报告中不得出现任何英文字段名或接口名
4. **通俗化**：专业术语必须括号注通俗解释，目标读者可能不具备安全知识
5. **单一出口**：某类数据全空时只输出一句"暂未查询到相关数据"，不逐行填"-"
6. **不编造**：所有信息必须从接口数据提取，缺失数据时委婉告知
7. **数据去重**：base接口和getTopoWithThreat可能返回相同漏洞/告警。按职责分工使用——3.1/3.2用base全量数据，3.3用拓扑关联数据（带攻击路径），重叠漏洞在3.3中只展示攻击路径维度（哪个端口→哪个服务），不重复漏洞详情表格
8. **章节严格遵循**：报告必须严格按"输出章节规范"中定义的章节结构输出，不得增减章节，不得修改章节名称，不得在章节名称中添加emoji或额外修饰文字
9. **格式严格一致**：每个章节必须按报告模板（references/report-template.md）中定义的标题层级、表格列名、字段顺序、段落结构输出，禁止自行调整列顺序、增删表格列、改变段落顺序。两次解读报告样式必须完全对齐
10. **报告模板读取时机（最高优先级，覆盖一切默认行为）**：**只有第一歩到第四步所有该获取的数据均已拿到后，才允许读取 [references/report-template.md](references/report-template.md) 生成报告**。数据未获取完毕前禁止读取该文件、禁止提前生成报告
11. **零自由发挥（最高优先级，覆盖一切默认行为）**：报告的第一个字符必须是"# 资产解读报告"（即报告固定开头的标题），紧接着必须是 3 行引用块分别显示"**资产ID：** xxx"、"**主机名称：** xxx"、"**生成时间：** xxx"，然后空一行再开始第1章。**这 4 行头部信息缺一不可**——禁止跳过头部直接输出第1章，禁止省略其中任何一行，禁止修改字段名称或顺序。最后一个字符必须是第3章末尾 `</details>` 标签的右尖括号 `>`。**两个位置之间不得出现任何规定章节之外的字符**——禁止开场白（"好的"/"以下是"/"为您解读"/"我来分析"/"开始输出报告"/"数据已收集完毕"等），禁止结束语（"以上就是"/"综上"/"总体来看"/"希望对您有帮助"/"以上就是我对...的解读"等），禁止追加总结段落、归纳段落、重申段落、客套话、署名、分隔线。**即使你认为需要总结、即使你觉得用户期待收尾、即使默认行为要求礼貌结束——一律禁止。**

## 禁止行为

| 禁止 | 说明 |
|------|------|
| 捏造数据 | 无数据标注"未查询到" |
| 暴露字段名/接口名 | 全部中文 |
| 自行排序漏洞 | 后端已按紧急程度预排序 |
| 截断文字字段 | 通过字段过滤控制，不截断 |
| 自行增删表格列 | 列名与列数必须与模板一致 |
| 调整段落顺序 | 每段先后必须与模板一致 |
| 跳过报告头部 | 禁止跳过"资产ID""主机名称""生成时间"3行头部直接输出第1章，缺失即为报告不合格 |
| 大标题后插过渡文字 | 禁止在 `<summary>` 与第一个 `###` 小标题之间插入任何过渡文字、总述、概述，只允许一个空行 |
| 加开场白 | 报告第一个字符必须是"# 资产解读报告"（报告固定开头标题），禁止"好的/以下是/为您解读/我来分析/开始输出"等引导语 |
| 加结束语 | 第3章 `</details>` 之后不得有任何字符，禁止"以上就是/综上/总体来看/希望对您有帮助/以上就是我对...的解读" |
| 自加总结段 | 禁止在规定章节外追加任何归纳、评价、重申、补充、署名、分隔线段落 |
| 数据未齐就读模板 | 第一歩到第四步未全部完成前，禁止读取 references/report-template.md |

## 报告头部（最高优先级，必须输出）

**每份报告必须以下面 4 行作为开头，顺序、格式、字段名均不可变。空行也要保留。缺失任何一行即为报告不合格。**

```
# 资产解读报告
> **资产ID：** [ASSET_ID]
> **主机名称：** [HOST_NAME]
> **生成时间：** [YYYY-MM-DD HH:MM]

```

**字段取值来源**：
- `ASSET_ID`：从 `base_extractInfoForInterpret` 返回的 `asset_info.ASSET_ID` 取
- `HOST_NAME`：从 `asset_info.HOST_NAME` 取；缺失时填"—"
- `YYYY-MM-DD HH:MM`：报告生成时刻（当前时间），格式固定为 `YYYY-MM-DD HH:MM`，用 24 小时制

**禁止**：在报告头部前加"好的/以下是/为您解读"等引导语；在头部与第1章之间插入额外说明、目录、摘要；跳过头部直接输出第1章。

## 执行流程

**必须严格按步骤执行，所有数据获取完成后才输出报告。**

### 第一步：基础数据
- `base_extractInfoForInterpret(bizType=4, bizId=资产ID)` → asset_info + vuln_info + alarm_info + event_info + weakPwd_info + lateralThreat_info(已聚合) + scoreHistory + risk_score
- `asset_getRiskPort(assetId)` 获取结果，用于获取资产风险端口信息
- `asset_fingerprintGroup(assetId)` → 指纹分类统计（数据库X个、WEB站点X个等），用于判断"资产上跑了什么"


### 第二步：统计概览（并行，极轻量）
以下三个工具必须调用：
- `vuln_getVulnLevelGroup(assetId)` → 漏洞等级分布
- `alarm_groupAlarm(groupFieldList="RISK_LEVEL", victimIp=资产IP)` → 告警等级分布
- `alarm_groupEvent(groupFieldList="RISK_LEVEL", victimIp=资产IP)` → 事件等级分布

### 第三步：评分关键节点调查

遍历 scoreHistory，找出所有**评分下降**的节点：
- 选下降点（最多5个，优先选降幅最大的）
- 每个调用 `asset_investigateScoreChange(assetId, assetIp, changeDate, scoreBefore, scoreAfter, xdrToken)`
- 评分上升节点不调查，简要带过（"告警被处置/漏洞修复"）
- 无下降节点时："评分基本稳定"

### 第四步：按需扩展
- `asset_getTopoWithThreat(assetId)` → 暴露资产或有攻击的资产调用。**返回已按"公网可达(50分)+告警数(5分/条)+CVE数(3分/条)"打分排序后的 top 5 高危端口节点**（summary.truncated=true 表示有更多节点被截断）。
- **弱密码关联**（base_extractInfoForInterpret 数据weakPwd_info不为空时调用）：
  - `base_execute_sub_skill(subAgentName="weak-password-analyzer",  params={"assetId":"资产ID","services":"从getTopoWithThreat的threatenedServices提取的服务名列表：例如mysql等"}, requirePrompt="将弱密码与拓扑服务关联，匹配到3个服务即可停止，返回概要")`
  - 子技能在自己的上下文中查询弱密码并匹配，匹配满3个服务后停止翻页，只返回概要结论，不污染主上下文
- 存在暴力破解/异常登录迹象时 → `asset_getLoginRecords(assetIp)`

### 第五步：输出报告

**前置条件（硬约束）**：第一歩到第四步所有该获取的数据均已拿到（含按需扩展接口的返回）。

使用base_read_reference(filePath=绝对路径)读取 [references/report-template.md](references/report-template.md)，按其中定义的报告开头、章节结构、表格列名、段落模板、空值模板、通用规则输出报告。
如果读取文件失败则应该继续尝试读取，多次失败后应该直接结束，返回:"读取文件模版失败，无法生成资产解读报告"
**禁止**：在数据未获取完毕前提前读取该文件；在报告输出过程中再回去调用工具补数据。
