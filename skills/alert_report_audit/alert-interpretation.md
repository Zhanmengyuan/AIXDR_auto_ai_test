# 告警解读报告

## 核心原则

1. **零前置输出**：报告内容必须从 `# 告警解读报告` 开始，前面严禁出现任何解释性、过渡性、思考性文字（如"现在我有了完整的告警信息，我来生成报告"、"基于以上数据，输出如下"等）。严禁输出报告内容以外的任何字符。
2. **统一输出6章**：第1→2→3→4→5→6，顺序不变，少一章算失败。
3. **第4/5/6章看威胁定性和攻击结果两个维度**：
   - 威胁定性=不能确认 → 第4/5/6章均只输出指定文案（最高优先级）
   - 威胁定性=误报 → 第4章输出"告警经研判为误报，无实际攻击影响。"第5章输出"告警经研判为误报，无后续攻击风险。"第6章输出误报确认与规则优化建议
   - 威胁定性=正报 且 攻击结果=成功 → 第4/5章填详细内容，第6章填处置建议
   - 威胁定性=正报 且 攻击结果=失败/未知 → 第4/5章只输出指定文案，第6章填排查建议
4. **第6章看威胁定性和攻击结果两个维度**：
   - 威胁定性=不能确认 → 只输出"威胁定性尚未确认，暂无法给出针对性建议，请先补充第1章列出的缺失信息以完成定性。"（最高优先级）
   - 威胁定性=误报 → 输出误报确认建议与规则优化建议
   - 威胁定性=正报，攻击结果=成功 → 填处置建议
   - 威胁定性=正报，攻击结果=失败/未知 → 填排查建议
5. **两个维度严禁混淆**：第1章写"正报/误报/不能确认"，第3章写"成功/失败/未知"。
6. **字段优先于一切证据**：引擎已返回的字段值（`ALERT_RESULT_FLAG`、`AI_RESULT`、`RESULT`）优先于任何日志、响应码、进程痕迹等原始证据。严禁用原始证据去"验证"或"推翻"字段值。
7. **零字段名**：全文不准出现 RESULT、AI_RESULT、ALERT_RESULT_FLAG、asset_info 等任何英文字段名。
8. **严禁捏造**：缺失证据只准写证据类型名称，不准编造具体路径、命令示例、IP地址。
9. **建议分层可操作**：排查/处置建议必须分层（快速验证→范围排查→深层取证），必须根据告警类型动态调整重点，给出可执行命令，禁止笼统描述。
10. **一句话总结与第3章攻击结果的描述必须自洽**：一句话总结中对攻击结果的描述必须与第3章最终判定的"成功/失败/未知"完全一致，严禁矛盾。

## 第一步：抽取告警精简信息

仅需调用 `base_extractInfoForInterpret(bizType=1, bizId=当前告警SNOW_ID)` 获取告警及其相关数据。

**入参说明：**
- `bizType` 固定为 `1`
- `bizId` 从当前告警上下文的 `SNOW_ID` 获取

## 场景化字段关注指引

根据告警的检测类型和攻击特征，从告警数据中提取相关信息。没有的信息写"未查询到"或"—"。

### 威胁定性相关
- 读取 `ALERT_RESULT_FLAG`，值为1→正报，2→误报，3或空→不能确认。**严禁自己判定**

### 攻击结果相关
- 按优先级读取 `AI_RESULT` → `RESULT`，取最终结论。**严禁自己判定**
- **2个字段全部为空时，攻击结果必须为"未知"，严禁AI基于日志内容自行推断成功或失败。**
- **攻击链阶段判定**：基于 `KILL_CHAIN` 和 `TAC_NAME` 字段，明确当前告警处于什么阶段。

### 告警涉及网络实体
- 读取 `ATTACKER_IP`（源IP）、`ATTACKER_PORT`（源端口）、`ATTACKER_COUNTRY`/`ATTACKER_PROVINCE`/`ATTACKER_CITY`（源属地）、`DIRECTION`（流量方向）。
- 读取 `VICTIM_IP`（目的IP）、`VICTIM_PORT`（目的端口）、`VICTIM_COUNTRY`/`VICTIM_PROVINCE`/`VICTIM_CITY`（目的属地）。
- 读取 `HTTP_REQ_HOST`（请求域名）、`IOC_RESOURCE`（情报关联IOC）。
- 若 `intelligence_info` 命中，读取 `MALDIUM_THREAT`（情报标签）、历史攻击记录。
- **不强行分配攻击者/受害者角色**，只陈述告警中出现的网络实体事实。

### 受影响资产（平台识别）
**判定规则（优先级）：**
1. **优先从 `AFFECTED_ASSET_INFO` / `asset_info` 读取**（平台已识别的受影响资产，最准确）。资产IP = `AFFECTED_ASSET_INFO.IP` 或 `asset_info.IP`，资产名称/类型/等级/业务系统/操作系统/责任人/状态等均从该对象读取。
2. **`AFFECTED_ASSET_INFO` / `asset_info` 为空时**，结合 `DIRECTION` 从 `ATTACKER_IP`/`VICTIM_IP` 推断受影响资产：
   - `DIRECTION` = "外对内" → 受影响资产IP = `VICTIM_IP`
   - `DIRECTION` = "内对外" → 受影响资产IP = `ATTACKER_IP`（内网主机主动外联，内网主机为受影响资产）
   - `DIRECTION` = "内对内" → 受影响资产IP = `VICTIM_IP`（通常目的端为受影响资产，需结合告警类型确认）
   - `DIRECTION` = 空/其他 → 标注"攻击方向未明确，无法确定受影响资产IP"，此时资产详情均写"未查询到"
3. **涉及资产时**（`AFFECTED_ASSET_INFO` / `asset_info` 存在，或 `VICTIM_ASSET_ID` 不为空），需同时调用 `asset_pageAsset` + `asset_fingerprintPage` 获取资产详情和资产指纹（运行服务、中间件、数据库、开放端口、操作系统、责任人 [取`OWNER_NAME`字段，为空就展示-]）。

### 挖矿取证相关
- 读取 `MINING_POOL`（矿池域名）、`MINING_CURRENCY`（挖矿币种）、`MINING_STAGE`（挖矿阶段）、`MINING_ADDR`（矿池IP地址）。

### 情报关联相关
- 读取 `intelligence_info` 中的 `MALDIUM_TYPE_DESC`（情报类型）、`MALDIUM_DESC`（威胁描述）、`MALDIUM_THREAT`（恶意标签）、`MALDIUM_CONFIDENCE`（置信度）、`MALDIUM_SEVERITY`（情报等级）、`IOC_RESOURCE`（关联IOC）、`INTEL_NAME`（情报名称）。

## 强约束判定规则

### 威胁定性判定（机械取值，严禁推理）

**判定流程（必须严格执行，不准跳过任何步骤）**：

```
Step 1 → 读取 ALERT_RESULT_FLAG 字段的原始值
Step 2 → 原始值 = "1" → 结论 = 正报
Step 3 → 原始值 = "2" → 结论 = 误报
Step 4 → 原始值 = "3"、空值、或不存在 → 结论 = 不能确认
Step 5 → 严禁在Step 1-4之外添加任何判断逻辑
```

**铁律**：`ALERT_RESULT_FLAG` 的值是引擎已判定的最终结论，模型只准做"值→结论"的机械映射，不准做语义分析、不准做证据补强、不准做质疑修正。即使告警描述看起来很像攻击，只要该字段=2，结论必须是误报；只要该字段=3或空，结论必须是不能确认。

**输出表述要求**：判定依据中严禁引用具体字段名说明缺失原因。
- 正确示例："信息不充分，无法完成告警定性"
- 错误示例："引擎未返回明确的正报/误报标识"（暗示AI解读无价值，严禁出现）
- 错误示例："ALERT_RESULT_FLAG为空"（暴露字段名，严禁出现）

### 攻击结果判定（机械取值，严禁推理）

**判定流程（必须严格执行，不准跳过任何步骤）**：

```
Step 1 → 读取 AI_RESULT 字段的原始值
Step 2 → AI_RESULT 非空 → 结论 = AI_RESULT 的值（成功/失败/未知），流程结束
Step 3 → AI_RESULT 为空 → 读取 RESULT 字段的原始值
Step 4 → RESULT 非空 → 结论 = RESULT 的值（成功/失败/未知），流程结束
Step 5 → AI_RESULT 和 RESULT 都为空/不存在 → 结论 = 未知，流程结束
Step 6 → 严禁在Step 1-5之外添加任何判断逻辑
```

**铁律**：`AI_RESULT` 和 `RESULT` 是引擎已判定的最终结论，模型只准做"值→结论"的机械映射。即使HTTP响应码是200、即使进程已启动、即使文件已落地，只要这两个字段全空，结论必须是"未知"；即使AI_RESULT="成功"但你觉得"证据不足"，结论也必须是"成功"。

**输出表述要求**：攻击结果表述统一为"经综合研判"，严禁说明判定依据或字段来源。

**常见错误（严禁出现）**：

| 错误类型 | 错误示例 | 正确做法 |
|---------|---------|---------|
| 威胁定性-自行推断 | `ALERT_RESULT_FLAG=1`，但模型认为"告警特征不明显"输出"不能确认" | 直接输出"正报" |
| 威胁定性-字段混淆 | 把 `RESULT` 的值当作威胁定性使用 | 威胁定性只认 `ALERT_RESULT_FLAG` |
| 攻击结果-自行推断 | `AI_RESULT`和`RESULT`都为空，但HTTP 200所以输出"成功" | 必须输出"未知" |
| 攻击结果-推翻引擎 | `AI_RESULT="成功"`，但模型认为"缺乏后续证据"改为"未知" | 必须输出"成功" |
| 两维度混淆 | 威胁定性="误报"，攻击结果输出"失败" | 两维度独立读取，误报时攻击结果仍按字段取值 |

### 分支规则（决定第4/5/6章填什么）

优先级从高到低：
1. **第1章威胁定性写"不能确认" → 第4/5/6章均只输出指定文案**（最高优先级，覆盖下面所有规则）
2. **第1章威胁定性写"误报" → 第4/5/6章均只输出误报专用文案**
3. **第3章攻击结果写"成功" 且 第1章威胁定性写"正报" → 第4/5/6章填详细内容**
4. **第3章攻击结果写"失败"或"未知" 且 第1章威胁定性写"正报" → 第4/5章只输出指定文案，第6章写排查建议**

第4章指定文案：
```
当前攻击结果未确认成功，暂无法评估当前攻击影响。
```

第5章指定文案：
```
当前攻击结果未确认成功，暂无法预测后续风险。
```

第6章指定文案（仅威胁定性=不能确认时使用）：
```
威胁定性尚未确认，暂无法给出针对性建议，请先补充第1章列出的缺失信息以完成定性。
```

误报专用文案：
- 第4章：`告警经研判为误报，无实际攻击影响。`
- 第5章：`告警经研判为误报，无后续攻击风险。`
- 第6章：输出误报确认建议与规则优化建议（见第6章模板）

## 铁律

1. **统一输出6章**：第1→2→3→4→5→6，顺序不准变，少一章算失败。
2. **第4/5/6章看威胁定性和攻击结果两个维度**：不能确认→固定文案；误报→误报专用文案；正报+成功→详细内容/处置建议；正报+失败/未知→固定文案/排查建议。四套不准混填。
3. **误报≠攻击未成功**：误报意味着告警本身就不是真实攻击，第4/5章输出"无攻击影响/无攻击风险"，第6章聚焦误报确认和规则优化，严禁把误报和"攻击失败"混为一谈。
4. **攻击载荷单一出口**：三个分类均无值时只输出"未提取到攻击载荷信息。"，不准输出分类标题，不准逐行列"—"。
5. **两个维度严禁混淆**：第1章写"正报/误报/不能确认"，第3章写"成功/失败/未知"。
6. **零字段名**：全文不准出现 RESULT、AI_RESULT、ALERT_RESULT_FLAG、asset_info 等任何英文字段名；判定依据中严禁引用字段名说明缺失原因。
7. **严禁推翻引擎结论**：引擎已判定成功/失败的，严禁以"证据不足""缺乏佐证"等理由修正为未知。只有全部引擎结果为空时，才允许判断为未知。
8. **严禁捏造**：缺失证据清单只准写证据类型名称，不准编造具体路径、命令示例、IP地址。
9. **建议要分层并且可执行**：排查/处置建议必须按"快速验证→范围排查→深层取证"三层组织，必须根据告警类型动态调整重点，必须给出可执行命令（含参数，不能有语法错误），禁止"进一步排查""加强监控""建议关注"等笼统描述。
10. **第4章不准矛盾**：第2章有资产的，第4章（成功时）不准写"未查询到受影响资产信息"。
11. **空值不输出**：第2章关键实体中，值为空的字段不输出该行，禁止输出"属性：-"格式。
12. **一句话总结的格式**：必须加粗（** **），单行展示，且攻击结果描述与第3章不冲突。
13. **第2章与第3章边界清晰**：第2章只输出客观攻击载荷数据，第3章只输出结果性证据，严禁内容重复混淆。
14. **攻击链阶段必须展示**：第3章必须输出攻击链阶段，用于明确"成功"的语义边界。
15. **未知状态差异化**：未知状态的缺失证据必须按告警类型（终端/网络/认证/情报）差异化输出，严禁所有类型共用同一套缺失证据模板。
