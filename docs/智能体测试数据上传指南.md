# 智能体测试数据上传指南

> 各位智能体测试负责人：
> 本指南告诉你如何把测试结果上传到统一测试框架。只需两步：**填JSON + curl上传**。

> ⚠️ **【服务信息】**：
> - 服务地址：`http://10.21.179.193:8080`
> - 本次批次ID：`v190_20261118`（QA团队统一指定，所有智能体都用这个）

---

## 一、上传接口

```
POST http://10.21.179.193:8080/api/v1/results?agent_id={你的智能体ID}&run_id=v190_20261118&model={大模型标识}
```

- `agent_id`：你的智能体标识（见下方各智能体对照表）
- `run_id`：本次测试批次标识，统一为 `v190_20261118`
- `model`：大模型标识（见下方model值说明），本次测试跑在哪个大模型上

---

## 二、JSON格式

一个智能体上传一个JSON，结构如下（model 不放 JSON 里，通过接口参数传）：

```json
{
  "category": "detect",
  "total_samples": 600,
  "valid_samples": 600,
  "dimensions": {
    "accuracy": { ... },
    "performance": { ... }
  },
  "failed_samples": [],
  "invalid_samples": []
}
```

**字段说明**：

| 字段 | 必填 | 填什么 |
|------|:---:|--------|
| `category` | ✅ | 你的智能体分类（见下方分类值说明） |
| `total_samples` | ✅ | 总样本数 |
| `valid_samples` | ✅ | 有效样本数（≤总样本数） |
| `dimensions` | ✅ | 指标值（见下方各类型填法） |
| `failed_samples` | 有则填 | 失败样本列表，每项 `{"sample_id": "...", "reason": "..."}` |
| `invalid_samples` | 有则填 | 失效样本列表（业务数据不存在），同上 |

**category 分类值说明**：

| category值 | 含义 | 对应智能体 |
|-----------|------|-----------|
| `detect` | 检测研判类 | WAF降噪、恶意文件检测、Webshell检测、钓鱼邮件检测、本地情报提取 |
| `generate` | 内容生成类 | 安全告警解读、安全事件解读、资产解读、漏洞解读、沙箱文件解读 |
| `query` | 查询类 | text2sql、数字人知识查询 |
| `qa` | 知识问答类 | RAG检索 |

**model 值说明**：

| model值 | 含义 |
|---------|------|
| `180` | 180一体机 |
| `190` | 190一体机 |
| `cloud` | 云端大模型 |
| 具体型号名 | 直接填模型型号名，如 `kimi-2.6`、`deepseek-v4-pro`、`glm-5.2` 等 |

## 三、各类型指标怎么填

### 检测研判类（WAF降噪、恶意文件、Webshell、钓鱼邮件、情报提取）

准确性用F1，**你只需填4个黑白样本数量**，框架自动算F1：

```json
{
  "category": "detect",
  "total_samples": 600,
  "valid_samples": 600,
  "dimensions": {
    "accuracy": {
      "f1_score": {
        "black_samples": 300,     ← 黑样本总数（真实攻击/恶意样本）
        "black_correct": 291,     ← 黑样本判定正确的数量
        "white_samples": 300,     ← 白样本总数（正常/良性样本）
        "white_correct": 295      ← 白样本判定正确的数量
      }
    },
    "performance": {
      "avg_response_time": 9.74   ← 平均响应时间（秒）
    }
  },
  "failed_samples": [],
  "invalid_samples": []
}
```

### 内容生成类（告警/事件/资产/漏洞/沙箱解读）

准确性用整体内容合规性，**你填LLM审查分（0~100）**：

```json
{
  "category": "generate",
  "total_samples": 50,
  "valid_samples": 47,
  "dimensions": {
    "accuracy": {
      "content_compliance": 92    ← LLM审查分（0~100）
    },
    "performance": {
      "first_packet_time": 0.2,   ← 首包响应时间（秒）
      "avg_response_time": 21.2   ← 平均响应时间（秒）
    }
  },
  "failed_samples": [
    {"sample_id": "alarm_03", "reason": "AI调用超时"},
    {"sample_id": "alarm_07", "reason": "大模型连接异常"}
  ],
  "invalid_samples": []
}
```

### 查询类（text2sql、数字人知识查询）

准确性用结果准确率（0~1）：

```json
{
  "category": "query",
  "total_samples": 400,
  "valid_samples": 392,
  "dimensions": {
    "accuracy": {
      "result_accuracy": 0.848    ← 结果准确率（0~1）
    },
    "performance": {
      "avg_response_time": 18.6
    }
  },
  "failed_samples": [
    {"sample_id": "query_003", "reason": "SQL执行超时"}
  ],
  "invalid_samples": []
}
```

### 知识问答类（RAG检索）

准确性用答案正确性（0~1）：

```json
{
  "category": "qa",
  "total_samples": 430,
  "valid_samples": 430,
  "dimensions": {
    "accuracy": {
      "answer_correctness": 0.840  ← 答案正确性（0~1）
    },
    "performance": {
      "first_packet_time": 2.04,
      "avg_response_time": 18.58
    }
  },
  "failed_samples": [],
  "invalid_samples": []
}
```

## 五、上传命令

把JSON保存成文件后，用curl上传（model 填本次跑的大模型）：

```bash
curl -X POST "http://10.21.179.193:8080/api/v1/results?agent_id=waf_dedup&run_id=v190_20261118&model=190" \
  -H "Content-Type: application/json" \
  -d @waf_dedup_results.json
```

或者用Python：

```python
import requests

resp = requests.post(
    "http://10.21.179.193:8080/api/v1/results",

    json=data   # data 是你的JSON数据
)
print(resp.json())
```

## 七、常见问题

**Q1：我没有首包响应时间，怎么填？**
不填 `first_packet_time` 即可，只填 `avg_response_time`。

**Q2：我没有测某个维度，怎么填？**
不传那个维度即可。比如资产解读没有可靠性，`dimensions` 里不写 `reliability`。

**Q3：黑样本/白样本怎么定义？**
- 检测类：黑样本=真实攻击/恶意样本，白样本=正常/良性样本
- 情报提取：黑样本=含IOC的告警，白样本=不含IOC的告警

**Q4：失败样本和失效样本有什么区别？**
- failed_samples：AI调用失败（超时、连接异常、无响应）
- invalid_samples：AI正常返回，但业务数据查不到

**Q5：上传错了能重新传吗？**
可以，同一agent_id+run_id重新上传会覆盖之前的数据。

**Q6：服务地址和批次ID是多少？**
见本指南开头的"【服务信息】"，由QA团队统一告知。
