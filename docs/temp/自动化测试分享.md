# AIXDR 解读类模块 AI 自动化测试平台分享

> 分享人：AIXDR QA 团队
> 分享时间：2025年7月

---

## 一、背景与动机

### 问题来源

AIXDR 平台内置了多个 AI 解读智能体，分别负责对安全告警、安全事件、漏洞、资产进行自动化 AI 解读，生成供分析师参考的分析报告。

随着 AI 解读功能持续迭代，我们遇到了几个核心挑战：

- **质量难以量化**：AI 生成的报告好不好？靠人工看，效率低、标准不统一
- **稳定性无法保证**：同一条告警解读两次，结论会不会发生变化？
- **格式合规性缺乏验证**：章节结构、字段是否齐全、红线规则是否遵守？
- **回归效率极低**：每次模型迭代后，人工回归成本极高

### 解决思路

> **用 AI 测试 AI** —— 构建一套自动化评测闭环

引入外部 LLM（DeepSeek）作为"裁判"，对 AIXDR AI 生成的解读报告进行自动化质量审查，并量化输出评分结果，实现 7×5 定时自动运行。

## 三、核心功能详解

### 3.1 AI 解读质量测试

#### 实现原理

AIXDR 的 AI 解读接口基于 **SSE（Server-Sent Events）** 协议，AI 解读结果以流式方式实时推送。测试框架通过双线程协作精确捕获每个数据包：

```
主线程                          SSE 监听线程
  │                                  │
  ├──发送 Chat 请求 ───────────────►  │
  │                                  ├── 收到第1个非空包 → 记录"首包时间"
  │                                  ├── 持续接收解读内容
  │◄─── 收到终止信号 ───────────────  ├── 收到终止信号 → 停止计时、汇总内容
  │                                  │
  └──计算各项指标                     └──结束
```

**不同模块的终止信号不同**：
- 告警/事件：收到 `answerType=recommend_start` 停止计时（推荐问题开始生成，说明主报告已完成）
- 漏洞：收到 `<END_OF_TURN>` 信号
- 资产：收到 `answerType=confirm_plan_start` 信号

#### 样本三分类机制

测试过程中对每个样本进行分类，确保统计数据准确：

```
所有测试样本
    ├── 失败样本     AI 平台连接失败/大模型异常，不计入指标
    ├── 失效样本     API 查不到业务数据（记录本身无效），不计入指标
    └── 有效样本     正常参与所有指标计算
```

#### 各模块评测指标

**资产解读**

| 指标 | 说明 |
|------|------|
| 风险等级准确率 | AI 给出的风险等级与系统标准值是否一致 |
| 结构完整率 | 报告是否包含全部 3 个必需章节 |
| 首包时间 | 从发送请求到收到第一个内容包的时间 |
| 总响应时长 | 完整报告生成所需总时间 |

**安全告警 / 安全事件解读**

| 指标 | 说明 |
|------|------|
| 结构完整率 | 报告是否包含全部 6 个必需章节 |
| 威胁定性准确率 | AI 给出的威胁定性与系统标准值是否一致 |
| 攻击结果准确率 | AI 判断的攻击结果与系统标准值是否一致 |
| 推荐问题合格率 | 推荐问题的规范性、关联性、多样性综合评分 |
| 首包时间 / 总时长 | 响应性能指标 |

**漏洞解读**

| 指标 | 说明 |
|------|------|
| 动态结构完整率 | 根据"是否需要立即处置"结论，动态校验必检章节 |
| 首包时间 / 总时长 | 响应性能指标 |

> **动态结构说明**：若 AI 判定"需要立即处置"，则必须额外包含"资产波及范围"章节；否则不作要求。

#### 推荐问题质量三维评估（LLM-as-a-Judge）

对 SSE 流中实时捕获的推荐问题，引入 LLM 进行三维度评分：

| 维度 | 通过阈值 | 判断方式 |
|------|---------|---------|
| 规范符合度（字数/实体/工具边界/IP规则） | ≥ 0.8 | LLM 评分 |
| 报告关联性（实体来源于报告内容） | ≥ 0.8 | LLM 评分 |
| 问题多样性（覆盖不同排查方向） | ≥ 0.8 | LLM 评分 |

三个维度均达标才计为合格。

### 3.2 LLM 自动审查（AI 评测 AI）

#### 核心设计理念

> 不让 LLM 自由发挥，而是给它一份严格的规范说明书（SKILL.md），让它按规矩逐条审查

#### 审查流程

```
① 读取 AI 解读原始 Markdown 报告
       ↓
② 加载对应模块的审查规范（SKILL.md 作为 System Prompt）
       ↓
③ 调用 DeepSeek 执行逐条规则审查，输出违规规则 ID 列表
       ↓
④ 调用 score_calculator.py 按规则 ID 精确扣分（禁止 LLM 自行算分）
       ↓
⑤ 生成包含违规详情、扣分明细、纠错指引的审查报告（_audit.md）
       ↓
⑥ 汇总所有报告，生成 HTML 可视化综合报告
```

#### 技能规范库（SKILL.md）

为每个解读模块设计了独立的评审规范，以**告警审计**为例：

**5 大维度、31 条规则、100 分制**

| 维度 | 分值 | 规则示例 |
|------|------|---------|
| 结构完整性 | 20 分 | 头部元数据完整（4分）、6章顺序正确（4分） |
| 逻辑分支合规 | 30 分 | 不能确认分支固定句正确使用（6分）、误报分支规范（6分） |
| 内容质量 | 10 分 | 第3章攻击链阶段+举证（2分） |
| 红线合规 | 20 分 | 零英文字段名（12分） |
| 处置建议质量 | 20 分 | 分层结构规范（5分）、可执行命令（4分） |

**漏洞审计**：5 大维度、40 条规则、100 分制

#### 评级体系

| 分数区间 | 评级 | 含义 |
|---------|------|------|
| ≥ 90 分 | 完全合规 | 可直接发布 |
| 60 ~ 89 分 | 局部瑕疵 | 需微调后发布 |
| ≤ 59 分 | 严重违规 | 驳回重写 |

#### 关键设计：score_calculator.py

每个模块的计分脚本是**唯一权威得分来源**，不允许 LLM 自行计算分数，避免"AI 加法错误"和主观升降级：

```bash
# 传入违规规则 ID，输出精确扣分表
python3 skills/alarm_report_audit/score_calculator.py BR-03 RED-01

# 自检验证
python3 skills/alarm_report_audit/score_calculator.py --selftest

# 查看所有规则清单
python3 skills/alarm_report_audit/score_calculator.py --rules
```

### 3.3 核心结论稳定性测试

#### 测试逻辑

对同一条告警/事件/漏洞，**连续触发两次 AI 解读**，比较两次核心结论是否一致。

| 模块 | 提取的核心结论 | 判断方式 |
|------|--------------|---------|
| 告警 / 事件 | "一句话总结"字段 | LLM 语义一致性裁判 |
| 漏洞 | "是否需要立即处置"（是/否） | 规则精确匹配 |

#### 稳定性结果分类

| 结果 | 含义 | 是否计入通过率 |
|------|------|--------------|
| Pass | 两次结论一致 | 是 |
| Fail（结论不一致） | 两次结论有实质性差异 | 计入失败 |
| Fail（结论缺失） | 报告未输出核心结论字段 | 计入失败 |
| 执行错误 | AI 平台连接失败 | **不计入**通过率统计 |

#### LLM 语义裁判（告警/事件）

稳定性裁判不做简单字符串对比，而是用 LLM 判断两次"一句话总结"的**核心语义**是否一致：

```
判断规则：
1. 威胁类型、攻击结果、关键实体等核心意思一致 → 稳定
2. 核心意思有实质性差异 → 不稳定
3. 表达方式不同但核心结论相同 → 算稳定

输出：{"is_stable": true/false, "reason": "...", "inconsistencies": [...]}
```

## 六、技术亮点

### 亮点1：三段式评测闭环

```
解读执行  ──►  LLM 审查  ──►  稳定性验证
   │               │               │
量化性能         量化质量         量化可靠性
```

三个维度相互补充，覆盖 AI 解读质量的完整生命周期。

### 亮点2：AI 评测 AI（双 LLM 架构）

- **被测 LLM**：AIXDR 内置 AI 解读智能体（生成解读报告）
- **裁判 LLM**：DeepSeek-v4-pro（审查解读质量、判断稳定性）

两者各司其职，形成"考生 + 评卷老师"的分离架构。

### 亮点3：规则驱动，禁止 AI 自由计分

```
SKILL.md（规范说明书）
    → LLM 识别违规规则 ID（如 BR-03、RED-01）
    → score_calculator.py 精确计分（程序控制）
    → 禁止 LLM 直接给出分数
```

避免了 LLM 计分的主观性和加法错误，保证评分可重复、可审计。

### 亮点4：SSE 流精确计时

不同解读模块以不同信号作为"报告完成"的终止点，测量的是**"用户看到完整报告"的时刻**，而非"数据流结束"的时刻，更贴近真实用户体验。

### 亮点5：失效样本隔离

API 查不到业务数据的样本（记录本身无效）单独标记为"失效"，不参与指标计算，避免数据污染导致指标虚低。

### 亮点6：漏洞动态章节逻辑

漏洞解读的结构完整率不是固定的，而是根据 AI 自身的研判结论动态确定必检章节，避免"评测规则与 AI 业务逻辑冲突"的问题。

## 九、总结与展望

### 已实现

- 解读质量测试：多维指标自动化采集，每次运行 200 个样本
- LLM 自动审查：31~40 条规范规则，输出精确评分和纠错指引
- 稳定性测试：同 ID 双次对比，语义级别的一致性判断
- 全自动化运维：7×5 工作日定时执行，飞书即时通知

### 后续规划

- 引入历史数据趋势对比，自动检测模型迭代后的质量退化
- 扩大测试样本规模，增加边界场景覆盖
- 支持多环境并行测试（生产环境 vs 测试环境）
- 在 CI/CD 流水线中集成，实现模型发布前的自动质量门控
