## 一、产品概述

### 1.1 产品定位

AIXDR 智能体测试平台，是一个 Web 化服务，将现有的"智能体统一测试框架"升级为完整的产品，统一管理所有 AI 智能体的测试数据、生成测试报告、支持版本对比和趋势分析。

### 1.2 目标用户

| 用户角色 | 核心诉求 | 主要使用功能 |
|---------|---------|-------------|
| **QA 测试团队** | 管理测试批次、上传数据、生成报告 | 批次管理、数据上传、报告查看 |
| **开发人员** | 查看自己负责智能体的测试结果、定位问题 | 智能体详情、失败样本下钻 |
| **领导/管理层** | 看整体水平、版本迭代效果、趋势 | 综合报告、版本对比、趋势分析 |

### 1.3 核心价值

```
现状：测试数据散落在 JSON 文件里，靠命令行生成静态 HTML 报告
目标：数据入库统一管理，Web 页面随时查看，支持对比和趋势
```

| 现状痛点 | 产品价值 |
|---------|---------|
| 报告是静态 HTML，要手动打开 | Web 页面在线查看，随时访问 |
| 数据在 JSON 文件里，难追溯 | 数据库存储，历史数据可查 |
| 版本对比靠人工 | 在线选择两个批次对比 |
| 无法看历史趋势 | 趋势曲线展示分数变化 |
| 失败样本难溯源 | 页面下钻查看失败详情 |

## 四、数据库设计

### 4.1 数据库选型

| 方案 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| **SQLite** | 零配置、单文件、轻量 | 并发写入弱 | 小团队内部工具（推荐先用） |
| PostgreSQL | 功能强、并发好 | 需要部署维护 | 长期规模化 |

**建议**：先用 SQLite 快速落地（延续现有轻量风格），后续数据量大了再迁移 PostgreSQL。

### 4.2 ER 关系图

```
agents（智能体）1 ──────── N results（测试结果）N ──────── 1 batches（批次）
      │                              │
      │                              ├── N metrics（指标）
      │                              └── N samples（失败样本）
      │
      └── 从声明文件 config/agents/*.yaml 导入
```

### 4.3 表结构设计

#### 表1：agents（智能体表）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | INTEGER PK | 主键自增 | 1 |
| agent_id | VARCHAR(50) UNIQUE | 智能体标识 | ai_interpret_alarm |
| name | VARCHAR(100) | 中文名 | 安全告警解读 |
| category | VARCHAR(20) | 分类 | generate |
| team | VARCHAR(50) | 负责团队 | 解读组 |
| created_at | DATETIME | 创建时间 | 2026-11-18 |

> 数据来源：从 `config/agents/*.yaml` 声明文件导入。

#### 表2：batches（批次表）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | INTEGER PK | 主键自增 | 1 |
| run_id | VARCHAR(50) UNIQUE | 批次标识 | v190_20261118 |
| model | VARCHAR(50) | 大模型型号名 | 190 |
| test_date | DATE | 测试日期 | 2026-11-18 |
| description | VARCHAR(200) | 批次描述 | 190版本例行测试 |

#### 表3：results（测试结果表）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | INTEGER PK | 主键自增 | 1 |
| agent_id | VARCHAR(50) | 智能体标识（外键） | ai_interpret_alarm |
| run_id | VARCHAR(50) | 批次标识（外键） | v190_20261118 |
| model | VARCHAR(50) | 大模型型号名（冗余） | 190 |
| category | VARCHAR(20) | 分类（冗余） | generate |
| total_samples | INTEGER | 总样本数 | 2 |

> 唯一约束：`(agent_id, run_id)` 唯一，同一智能体同一批次只有一条。

#### 表4：metrics（指标表）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | INTEGER PK | 主键自增 | 1 |

#### 表5：samples（失败/失效样本表）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | INTEGER PK | 主键自增 | 1 |
| result_id | INTEGER | 结果ID（外键） | 1 |

| created_at | DATETIME | 创建时间 | 2026-11-18 |

> 一个 result 有多个 sample（失败/失效样本，用于下钻溯源）。

### 4.4 数据库初始化 SQL

```sql
-- 智能体表
CREATE TABLE agents (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    agent_id VARCHAR(50) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    category VARCHAR(20) NOT NULL,
    team VARCHAR(50),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 批次表
CREATE TABLE batches (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id VARCHAR(50) UNIQUE NOT NULL,
    model VARCHAR(50) NOT NULL,
    test_date DATE,
    description VARCHAR(200),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 测试结果表
CREATE TABLE results (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    agent_id VARCHAR(50) NOT NULL,
    run_id VARCHAR(50) NOT NULL,
    model VARCHAR(50),
    category VARCHAR(20),
    total_samples INTEGER,
    valid_samples INTEGER,
    agent_score FLOAT,
    rating VARCHAR(5),
    uploaded_at DATETIME,
    UNIQUE(agent_id, run_id)
);

-- 指标表
CREATE TABLE metrics (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    result_id INTEGER NOT NULL,
    dimension VARCHAR(20) NOT NULL,
    metric_key VARCHAR(50) NOT NULL,
    metric_value TEXT,
    detail TEXT
);

-- 失败样本表
CREATE TABLE samples (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    result_id INTEGER NOT NULL,
    sample_id VARCHAR(100) NOT NULL,
    reason VARCHAR(200),
    sample_type VARCHAR(20),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 五、技术架构

### 5.1 技术选型

| 层次 | 技术 | 说明 |
|------|------|------|
| 后端 | FastAPI | 延续现有 run_server.py |
| 数据库 | SQLite + SQLAlchemy ORM | 轻量，后续可换 PostgreSQL |
| 前端 | Jinja2 模板 + 原生 JS + ECharts | 轻量前端，趋势图用 ECharts |
| 评分引擎 | 现有 scoring_engine.py | 复用，不变 |
| 声明文件 | 现有 config/agents/*.yaml | 复用，导入数据库 |

### 5.2 系统架构

```
┌─────────────────────────────────────────────────┐
│  前端（Jinja2 模板 + JS + ECharts）              │
│  报告页 | 对比页 | 趋势页 | 详情页 | 管理页        │
└──────────────────────┬──────────────────────────┘
                       │ HTTP / JSON
┌──────────────────────┴──────────────────────────┐
│  后端（FastAPI）                                 │
│  ├── 数据上传接口（保留现有 /api/v1/results）      │
│  ├── 报告查询接口（/reports/...）                 │
│  ├── 版本对比接口（/compare/...）                 │
│  ├── 趋势查询接口（/trend/...）                   │
│  └── 管理接口（/admin/...）                       │
└──────────┬───────────────────┬──────────────────┘
           │                   │
┌──────────┴──────────┐ ┌──────┴──────────────────┐
│  数据库（SQLite）     │ │  评分引擎（复用现有）      │
│  agents/batches/     │ │  scoring_engine.py      │
│  results/metrics/    │ │  声明文件 config/agents  │
│  samples             │ │                        │
└─────────────────────┘ └─────────────────────────┘
```

### 5.3 数据流

```
1. 各团队 curl 上传数据
   → POST /api/v1/results?agent_id=xxx&run_id=xxx&model=xxx
   → 校验 → 评分引擎算分 → 写入数据库（results/metrics/samples）

2. Web 页面查看报告
   → GET /reports/{run_id}
   → 后端从数据库查询 → 渲染 HTML

3. 版本对比
   → GET /compare?run_id_a=xxx&run_id_b=xxx
   → 查询两个批次 → 对比展示

4. 趋势分析
   → GET /trend/{agent_id}
   → 查询该智能体所有批次分数 → ECharts 折线图
```
